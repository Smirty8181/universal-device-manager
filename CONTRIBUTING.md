# Участие в разработке

## Перед началом

- Платформа: Windows 10/11 x64. Код использует SetupAPI, Raw Input, WASAPI и SendInput.
- Обсудите крупные изменения в issue: протоколы устройств и изменения схемы БД затрагивают совместимость.
- Не добавляйте функции «для вида»: каждая кнопка должна выполнять реальную операцию или быть явно отключена с объяснением.

## Стиль

**Rust**

- `cargo fmt` обязателен;
- `cargo clippy --all-targets -- -D warnings` без предупреждений;
- публичные команды и структуры документируются коротко, без пересказа очевидного;
- ошибки возвращаются через `Result<_, String>` на границе команд; внутренние модули используют типы.

**TypeScript / Vue**

- строгая типизация, без `any` в новом коде;
- компоненты не разрастаются: логика — в `lib/` и stores;
- строки интерфейса — в `src/lib/i18n.ts` (RU и EN);
- `npm run lint`, `npx vue-tsc -b`, `npm test` должны проходить.

## Новый адаптер устройства

1. Соберите доказательства: VID/PID, Hardware ID, HID-дескрипторы, отчёт диагностики.
2. Опишите транспорт и команды (только чтение, пока не подтверждена запись).
3. Реализуйте чтение, затем запись с проверкой ответа/повторным чтением.
4. Добавьте capability со статусом `working` только для проверенных функций; остальные — `research` или `unsupported`.
5. Добавьте unit-тесты для разбора пакетов.
6. Проверьте на физическом устройстве и укажите это в PR.

Запрещено:

- подбирать команды записи перебором;
- устанавливать драйверы/прошивки без официального источника и подтверждения;
- показывать фиктивные значения заряда или DPI;
- добавлять скрытый сбор ввода или обход античитов.

## Тесты

```bash
bash scripts/test-rust.sh
npm test
```

Тестовые exe на GNU требуют манифест Common-Controls — скрипт подключает его автоматически. Не удаляйте эту логику: без неё `cargo test` падает на загрузке.

## Коммиты и PR

- Один PR — одна тема; не смешивайте рефакторинг и новую функцию.
- Сообщение коммита: короткое, в императиве, без служебных пометок и метаданных инструментов.
- В PR опишите проверку: устройство, сценарий, результат, что осталось непроверенным.
- Не публикуйте результаты тестов, которых не было.
