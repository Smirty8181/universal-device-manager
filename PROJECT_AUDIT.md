# UDM — аудит проекта

Дата проверки: 31.10.2026. Платформа: Windows 11 x64, сборка Tauri 2.12.5 (GNU toolchain), WebView2.
Проверка — на собранном приложении: реальные устройства, чтение и запись протоколов, снимки интерфейса.

Документ фиксирует состояние кода и реально проверенные сценарии. Всё, что не проверялось на оборудовании, отмечено отдельно.

---

## 1. Карта архитектуры

```
Vue 3 + TypeScript + Pinia (src/)
  views/           17 экранов: обзор, устройства, Device Intelligence, RGB, студии,
                   визуализатор, автокликер, макросы, профили, база, драйверы,
                   диагностика, настройки, трей, overlay
  components/      карточки устройств, клавиатура, мышь, подсветка, батарея, UI-кит
  lib/             api.ts (IPC), типы, i18n, раскладки, форматирование, картинки
  stores/          app, devices, rgb, profiles, macros, input, visualizer
        │  invoke / event
        ▼
Rust (src-tauri/src/, ~12.7 тыс. строк)
  lib.rs           окна, трей, команды, фоновой монитор, профили
  devices.rs       PnP/SetupAPI + HID + Bluetooth, объединение интерфейсов
  battery.rs       HID Battery Strength, BLE 0x180F/0x2A19, vendor-источники
  telemetry.rs     телеметрия транспорта, ресиверы, capture, protocol sweep
  input.rs         Raw Input, low-level hooks, ремап, макросы, overlay-события
  autoclicker.rs   SendInput, F6, ограничения, статус
  alumix.rs        проверенный протокол подсветки Red Square Alumix
  ajazz.rs         DPI/частота/заряд AJAZZ AJ159 NL
  audio.rs         WASAPI-сессии, громкость, mute, Equalizer APO
  drivers.rs       SetupAPI, подпись INF, установка
  resolver.rs      официальные источники драйверов
  catalog.rs       каталог моделей и загрузка
  db.rs            SQLite: устройства, история, привязки, телеметрия
  registry.rs      локальная база моделей
  battery_rgb.rs   режим отображения заряда подсветкой
  hid_desc.rs, hid_lab.rs, ble.rs, macros.rs, store.rs, system.rs
        │
        ▼
SQLite (%APPDATA%\com.udm.desktop\device-db.sqlite) + logs + assets
```

Окна: `main`, `tray` (компактная панель 372×568), `overlay` (прозрачное, не забирает фокус).
Связь: типизированные команды Tauri; события `devices:update`, `keyboard:live`, `input:changed`, `macro:event`, `macro:state`, `settings:changed`, `autoclicker:state`.

### Ключевые решения

- Телеметрия строится на системных источниках (PnP, HID, BLE, Windows audio), а не на списке известных моделей. Неизвестное устройство остаётся в списке с HWID и доступными интерфейсами.
- Фирменные функции включаются только для протоколов, проверенных на реальном устройстве. Для остальных интерфейс объясняет причину, а не показывает декоративные регуляторы.
- Заряд показывается только при наличии источника; процент никогда не вычисляется «на глаз».
- Ввод обрабатывается Raw Input и low-level hooks; визуализатор не сохраняет текст, не пишет скрытый журнал и не блокирует ввод.
- Auto Clicker работает только по явному запуску, использует SendInput, останавливается по F6 и при выходе из приложения.

## 4. Производительность

- Полный скан устройств выполняется в фоновом потоке и не блокирует UI; список обновляется по событию.
- Трей и Device Intelligence читают кэш телеметрии, а не запускают новый скан при каждом открытии.
- Тяжёлые страницы (визуализатор, Intelligence) загружаются лениво через динамические маршруты.
- Частота обновления live-событий ограничена; история и счётчики хранятся в памяти с ограничением размера.
- Изображения устройств — WebP; карточки не перерисовываются при изменении несвязанного состояния.
- Остаточный риск: первичный скан PnP на машинах с сотнями устройств занимает заметное время; он выполняется асинхронно, но может увеличить первый рендер списка. Отдельного виртуализированного списка пока нет.

## 5. Изображения устройств: фактическое состояние

Реализовано:

- локальный каталог проверенных изображений для Red Square Alumix TKL, AJAZZ AJ159 NL, IO Graphite 2 Pro;
- сопоставление по registry ID и VID:PID, а не по «похожему» устройству;
- аккуратная заглушка для неизвестных моделей без выдачи её за реальное фото;
- офлайн-работа: изображения входят в сборку.

Не реализовано и почему:

- автоматический поиск по сайтам производителей не включён: у большинства сайтов нет публичного API, а автоматическая загрузка нарушает условия использования и может подставить чужую модель. Для добавления изображения нужна проверенная ссылка/файл и подтверждение модели. Каталог расширяется без изменения ядра.
- пользовательская загрузка изображений через интерфейс не добавлена: требует отдельного хранилища и проверки формата; в текущей версии каталог пополняется вместе с базой устройств.

## 6. Безопасность

Проверено:

- нет хранения токенов и паролей; приложение не имеет сетевой авторизации;
- сетевые загрузки (драйверы/каталог) идут по HTTPS с известных официальных источников, файлы проверяются; произвольные команды из конфигураций не выполняются;
- неподписанные драйверы не устанавливаются автоматически; установка только после подтверждения;
- прошивки не пишутся без документированного способа восстановления;
- HID-запись выполняется только для проверенных протоколов и известных устройств;
- визуализатор не сохраняет текст, не пишет скрытый журнал и не отправляет ввод в сеть;
- Auto Clicker не скрывается, не обходит античиты и не запускается сам;
- CSP ограничивает источники скриптов, стилей и соединений;
- Tauri capabilities ограничены окнами main/tray/overlay и минимальными разрешениями;
- приложение не требует администратора для обычной работы, установщик — per-user.

Остаточные риски:

- low-level hooks работают в пределах сессии пользователя; при сбое hook может быть снят Windows — приложение не эскалирует права;
- сторонние ассеты (изображения устройств) принадлежат производителям и используются для идентификации; при публикации нужно соблюдать их условия;
- автоматическая проверка зависимостей выполняется в CI; production-зависимости npm на момент проверки без известных уязвимостей.

Выполнено локально:

- `cargo fmt --check` — чисто;
- `cargo clippy --all-targets` — без предупреждений;
- Rust unit-тесты — 9/9 (парсинг путей HID, AJAZZ, конфиг Auto Clicker);
- `vue-tsc -b` — без ошибок;
- `eslint .` — без ошибок;
- Vitest — 38/38 в 4 файлах (форматирование, диапазоны Battery RGB, раскладки, компоненты);
- release-сборка и NSIS-установщик — успешно;
- живые проверки: устройства, заряд AJAZZ, визуализатор, overlay, Auto Clicker (лимит, задержка, таймер, double/hold, F6, остановка с фиксацией elapsed).

Не проверено:

- полный прогон на втором ПК и на чистой Windows без WebView2;
- BLE-батарея на подходящем BLE-устройстве;
- прошивка (нет официального сценария восстановления);
- macOS/Linux (проект Windows-only по используемым API);
- длительная нагрузка (многочасовой Auto Clicker, тысячи устройств).

## 9. Вывод

На момент аудита приложение собирается, запускается и выполняет заявленные функции на проверенном оборудовании. Неработающих кнопок и фиктивных панелей в production-интерфейсе не обнаружено: неподдерживаемые функции явно отключены с объяснением. Основные ограничения связаны не с кодом, а с закрытыми протоколами производителей и отсутствием части оборудования для проверки; они перечислены выше и в `SUPPORTED_DEVICES.md`.
