# Архитектура UDM

UDM — настольное приложение Windows на Tauri 2. Вся работа с оборудованием выполняется в Rust; Vue отвечает за отображение и ввод пользователя.

## Процессы и окна

| Окно | Назначение | Особенности |
|------|------------|-------------|
| `main` | Основной интерфейс | 1440×900, минимум 1120×700 |
| `tray` | Компактная панель из значка в трее | 372×568, открывается по клику, не запускает полный скан |
| `overlay` | Показ нажатий поверх игр | Прозрачное, always-on-top, не активируется (WS_EX_NOACTIVATE), закрывается без потери фокуса игры |

Маршрутизация — `createWebHashHistory`. Окна `tray` и `overlay` принудительно остаются на своих маршрутах. Страницы загружаются лениво.

## Поток данных

```
Windows API ──► Rust-модуль ──► команда Tauri ──► Pinia store ──► Vue-компонент
     ▲                                                                 │
     └──────────── событие (emit) ◄──────────────── invoke ────────────┘
```

Команды возвращают типизированные структуры (`src/lib/types.ts`). Долгие операции (скан, батарея, загрузка) выполняются в отдельных потоках и не блокируют webview.

События:

| Событие | Когда | Подписчики |
|---------|-------|------------|
| `devices:update` | изменился список или заряд | Dashboard, Devices, Tray |
| `keyboard:live` | Raw Input событие | Visualizer, Overlay |
| `input:changed` | ремап/хуки изменили состояние | Input, Settings |
| `macro:event` / `macro:state` | запись и проигрывание макросов | Macros, Tray |
| `settings:changed` | смена темы, языка, автозапуска | App shell |
| `autoclicker:state` | старт/остановка/прогресс | Auto Clicker, Tray |

## Rust-модули

| Модуль | Ответственность |
|--------|------------------|
| `devices` | SetupAPI PnP, hidapi, Bluetooth, объединение интерфейсов в одно устройство |
| `telemetry` | свойства транспорта, ресиверы, HID-дескрипторы, read-only sweep, capture |
| `battery` | HID Battery Strength, BLE GATT, vendor-источники, достоверность |
| `ajazz` | vendor-протокол AJAZZ AJ159 NL: заряд, DPI, polling |
| `alumix` | протокол подсветки Red Square Alumix: чтение, запись, подтверждение |
| `input` | Raw Input sink, WH_KEYBOARD_LL/WH_MOUSE_LL, ремап, макросная инъекция, live-статус |
| `autoclicker` | SendInput, лимиты, интервалы, F6, статус и события |
| `audio` | WASAPI-эндпоинты и сессии, громкость, mute, Equalizer APO |
| `drivers` | перечисление драйверов, проблема-коды, проверка подписи INF, установка |
| `resolver` | поиск официальных драйверов по Hardware ID |
| `catalog` | локальный каталог моделей и загрузка пакетов |
| `db` | SQLite: устройства, биндинги, история заряда, кэш телеметрии, бэкап |
| `battery_rgb` | расчёт сегментов заряда и применение к подсветке |
| `macros` | модель макросов, запись, воспроизведение, горячие клавиши |
| `store` | настройки, состояние приложения, лог |
| `system` | сведения о системе, автозапуск, завершение |
| `ble`, `hid_desc`, `hid_lab`, `registry` | BLE GATT, разбор дескрипторов, HID-лаборатория, база моделей |

## Хранилище

`%APPDATA%\com.udm.desktop\`:

| Путь | Содержимое |
|------|------------|
| `device-db.sqlite` | SQLite: реестр моделей (`devices`, `vendors`, `capabilities`, `sources`, `protocols`), `adapter_bindings`, `telemetry`, `history`, `proposals` |
| `settings.json` | настройки приложения |
| `profiles.json`, `macros.json` | профили и макросы |
| `battery.json`, `drivers.json`, `battery-rgb.json`, `input-map.json` | история заряда, история драйверов, режимы Battery RGB, карта ремапа |
| `logs/udm.log` | технический лог с ограничением размера |
| `drivers/` | загруженные официальные пакеты драйверов |
| `backups/` | резервные копии базы |
| `reports/` | экспортированные отчёты диагностики |

Миграции лежат в `src-tauri/migrations` и применяются при старте. Схема не содержит персональных данных; история ввода не сохраняется.

## Работа с оборудованием

- **Обнаружение.** PnP-перечисление через SetupAPI, HID-интерфейсы через hidapi, Bluetooth-устройства через Windows Runtime. Записи объединяются по физическому пути и VID/PID.
- **Заряд.** Приоритет: vendor-протокол → BLE Battery Service → HID Battery Strength → отсутствие данных. Каждое значение содержит источник.
- **RGB.** Только проверенные протоколы. Запись завершается чтением и сравнением; при несовпадении интерфейс сообщает об этом.
- **Ввод.** Raw Input для наблюдения, low-level hooks для ремапа. Собственная инъекция помечается `dwExtraInfo`, чтобы не зацикливаться.
- **Auto Clicker.** Отдельный поток, проверка `RUNNING/RUN_ID` на каждом шаге, пауза короткими тиками, чтобы остановка была быстрой. F6 обрабатывается в keyboard hook независимо от ремапа.

## Безопасность

- Никаких секретов и токенов в приложении нет.
- Сетевые запросы — только HTTPS к официальным источникам драйверов/каталога.
- Установка драйверов и прошивка требуют явного подтверждения; неподписанные пакеты отклоняются.
- CSP ограничивает источники контента.
- Права администратора не нужны для обычной работы.
